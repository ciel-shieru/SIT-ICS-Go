# PeopleSoft Navigation Flow

This documents timetable navigation after ADFS authentication. The browser remains open for PeopleSoft and BrightSpace fetching. The implementation is in `internal/browser/shared.go`.

1. **Navigate to the timetable endpoint.** `fetchTimetablePage()` checks the overall fetch context and binds the page to it. `navigateToTimetable()` retries the complete navigation cycle using `BrowserConfig.MaxRetries` and `RetryInterval`; each cycle has its own `NavigationTimeout` context and navigates to `https://in4sit.singaporetech.edu.sg/psc/CSSISSTD/EMPLOYEE/SA/c/SA_LEARNER_SERVICES.SSR_SSENRL_LIST.GBL`.
2. **Wait for and verify the destination.** The first URL check after navigation uses `WaitStable(5000)`; it reads `window.location.href` and compares the URL with the timetable endpoint after removing the query string. If that first check fails, use `WaitStable(1*time.Second)` for the second check and for every URL check in later whole-cycle retries. A second mismatch in a cycle fails that cycle and triggers a fresh navigation attempt under the same retry policy. Query parameters on the expected endpoint are allowed. A browser operation that reports success only after its operation context expires is treated as a failure.
3. **Open the term selector.** `handleMultiTermSelection()` calls `returnToTermSelection()`, which clicks `input[name='DERIVED_SSS_SCT_SSS_TERM_LINK']` and checks for `input[name='DERIVED_SSS_SCT_SSR_PB_GO']` using `WaitStable(5000)` followed by the first presence check. If absent or the query fails, it repeats `WaitStable(1*time.Second)` plus a Go-button check until the overall timetable-fetch context expires. It then verifies that `input.PSRADIOBUTTON` is present. If this navigation fails, the implementation tries to parse the current page as a fallback; the fallback is accepted only if parsing produces at least one entry. If no term radio buttons are found after returning, it uses the same guarded fallback.
4. **Fetch each term.** For each term radio button, click the radio button, click `input[name='DERIVED_SSS_SCT_SSR_PB_GO']`, wait with `WaitStable(2*time.Second)`, extract the page HTML, and parse it. Any click, stability, HTML extraction, or parsing error marks the complete multi-term fetch as failed; entries already collected from other terms are discarded.
5. **Recover between terms.** After a failed term, `restoreTermSelection()` checks for the Go button rather than relying on radio-button presence, because stale/hidden radio buttons can remain in the timetable-page DOM. If the Go button is absent, it clicks Change Term and validates the selector before continuing. Failure to restore the selector stops term iteration and fails the overall fetch.
6. **Retry the full PeopleSoft fetch.** Errors from initial navigation, term selection, term extraction, or event conversion are propagated to the enclosing retry wrapper. If retries are exhausted, the scheduler follows the configured degraded-fetch policy: non-fatal PeopleSoft failures allow BrightSpace fetching to continue while retaining cached PeopleSoft events; fatal browser/authentication failures abort the cycle.

The parser skips complete timetable rows containing a configured placeholder cell (currently `TBA`); other recognized malformed timetable rows fail parsing.
